## Honest constraints (read first)

1. **True 301s are not possible in this app.** It's a static Vite SPA on Lovable hosting; there is no server layer to emit HTTP 301. The existing redirects are client-side, which is exactly why 190 URLs sit in "Page with redirect". Real 301s must be configured in **Cloudflare Bulk Redirects / Rules** in front of the domain (the code already notes this). I'll produce the exact rule list to paste into Cloudflare, but I can't apply it from here.
2. **Task 1 and Task 3 conflict.** If robots.txt disallows `/travel-blog/`, Google can never see the redirect and those 190 URLs stay stuck forever. Correct order: ship the 301s in Cloudflare first, let Google reprocess, *then* block the path. So I'll add the `?replytocom=` and `/feed/` blocks now and leave `/travel-blog/` crawlable with a commented-out line.
3. **Task 2 (staging) can't be done here** — there's no staging environment in this codebase. If `staging.adventourist.in` is a separate WordPress/host, it needs its own robots.txt + password gate there.
4. **Tasks 3/5/6/7 need the actual exported URL lists.** I can't read Search Console exports; I can fix the categories I can see in code, but the per-URL 404/soft-404/5xx mapping needs those CSVs.

## What I will change in the app

### 1. robots.txt

- `Disallow: /*?replytocom=`
- `Disallow: /*/feed/`

### 2. Query-parameter and feed cleanup in the app
- Add a small router-level normaliser that strips WordPress junk query params (`replytocom`, `share`, `like_comment`) and trailing `/feed`, `/feed/`, `/amp`, `/1000` from any incoming path, then replaces history to the clean URL.
- Extend `LegacyRedirects.tsx` to cover the patterns named in the report that aren't handled yet: `/travel-stories/category/*`, `/tag/*`, `/author/*`, `/category/*`, and any `*/feed/` variant of those → `/travel-stories`.

### 3. Soft-404 prevention (Task 5, the part code can fix)
- `NotFound.tsx` currently renders a 200 with a short message — that is a textbook soft-404 signal, and `RootSlugRedirect` renders it for every unmatched root slug. I'll add `<SEO noIndex />` to it so unmatched pages are explicitly `noindex, nofollow` instead of thin 200s.
- Add `noIndex` to `/l/:slug` landing pages and the thank-you page (already robots-disallowed, but the tag makes it unambiguous).
- Audit trip and story detail pages: when a record is missing/unpublished, render the noindex not-found state rather than an empty templated shell.

### 4. Canonical audit (Task 7)
Spot-check every page using `<SEO />` to confirm `canonical` self-references its own route (not the homepage), and that `og:url` matches. I'll list anything that doesn't and fix it.

### 5. Sitemap hygiene (Task 4, code side)
The generator is already clean. I'll add a validation pass so that only entries whose slug exists and whose status is published/active are emitted, and log a warning for any dropped entry — so the sitemap can't drift back to including dead URLs.
